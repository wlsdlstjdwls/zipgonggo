# 파이프라인

공고 메타는 API로, 호실 목록은 첨부파일 파싱으로 얻는 이중 경로.
**파싱 실패를 정상 상태로 취급**하고 사람이 개입할 지점을 파이프라인 안에 못박는다.

## 단계

### S1 — 공고 목록 수집 ✅ 구현됨 (2026-09-08)

- **입력**: 마이홈포털 모집공고 API `HWSPR02/rsdtRcritNtcList` (1차) · LH청약플러스·서울주거포털 스크래핑(보조, 미구현)
- **코드**: `pipeline/src/zipgonggo_pipeline/sources/myhome.py`(클라이언트) · `stages/s1_collect.py`(적재)
- **실행**
  ```
  cd pipeline
  python -m zipgonggo_pipeline.stages.s1_collect            # 적재
  python -m zipgonggo_pipeline.stages.s1_collect --dry-run  # 호출·매핑만
  python -m pytest                                          # 매핑 단위 테스트 (샘플 JSON, 네트워크·DB 없음)
  ```
- **호출량**: `numOfRows=1000`이 통과해 전량(현재 ~360행)이 **호출 1회**. 개발계정 일 1,000건 한도에 무의미. 6시간 주기여도 하루 4회
- **행 → 공고 묶기**: API는 매입임대·전세임대 공고를 **시군구별 행**으로 쪼개 준다(`pblancId:houseSn` 같고 `signguNm`·`sumSuplyCo`만 다름). `source_key = pblancId:houseSn`으로 묶어 `notice` 1행 + `notice_area` N행. `notice.supply_count`는 합, `sigungu`는 하나일 때만 값
- **정정공고**: API가 원공고와 정정공고를 **둘 다** 현재 공고로 준다. 둘 다 별도 행·별도 URL. `amends_source_key = beforePblancId:houseSn`으로 연결. fingerprint에 이 키를 섞어야 유니크가 깨지지 않는다(실측 23쌍)
- **status 도출** (`derive_status`)

  | 조건 | 결과 |
  |---|---|
  | `endDe` 지남 | 접수마감 |
  | 원문 상태에 "정정" | 정정공고중 |
  | `beginDe` 도달 | 접수중 |
  | 그 외 | 공고중 |

  원문 값(`일반공고`·`정정공고`)은 `source_status`에 그대로
- **정규화**: 빈 문자열 → NULL. 보증금·월임대료·총세대수 0 → NULL(매입·전세임대는 전부 0으로 옴 = 미기재). 계약금·중도금·잔금 0은 유지
- **upsert**: `ON CONFLICT (source_key)`. `slug`·`source`·`publish`·`created_at`은 갱신 안 함(URL 불변). 공고 단위 SAVEPOINT라 1건 실패가 전체를 막지 않는다
- **미매핑 공급유형**: enum에 없는 `suplyTyNm`은 실패시키지 않고 `review_queue(reason=housing_type_unmapped)`에 넣고 스킵
- **기록**: 실행마다 `ingest_log(stage='S1')` 1행. 호출수·행수·insert/update/skip·오류 앞 20건
- **주기**: 6시간 (스케줄러 미구현)
- **실패 시**: 직전 스냅샷 유지. 수집 실패가 기존 페이지를 내리지 않는다
- **과거 공고**: API는 현재 공고만 준다. 연도별 아카이브는 파일데이터 15088707을 `source = myhome_file`로 백필(미구현)
- **API에 없는 기관**: SH·GH. 서울주거포털·GH 스크래퍼가 필요하다(미구현)

### S2 — 상태·마감 추적
- **입력**: LH 목록의 `상태`·`마감일`, 서울주거포털의 `발표일`
- **처리**: 매 수집마다 직전 스냅샷과 diff
- **출력**: `notice_event` — 신규 / 정정공고중 / 접수마감
- **쓰임**: D-day 카운터, "정정됨" 배지

### S3 — 첨부파일 수집·형식 분기
- **입력**: 공고 상세의 첨부 링크
- **처리**
  - XLSX·CSV → 그대로 표로
  - PDF → 텍스트 레이어 유무 판정 후 표 추출
  - HWP/HWPX → XML 변환 경유
- **출력**: `pipeline/data/attachments/` + `raw_snapshot` 레코드(파일 해시 포함)
- **해시를 보관하는 이유**: 정정공고로 파일이 교체되면 자동 감지된다
- **도구**: `pdfplumber`(표) · `pypdf`(레이어 판정) · `hwp5`/`hwpx`→XML · `openpyxl`

### S4 — 호실 레코드 파싱
- **추출**: 주소 · 단지명 · 동 · 호 · 전용면적(㎡) · 보증금/임대료(기본·전세전환·월세전환) · 층 · 방구조 · 승강기 · 비고
- **구조**: 기관·공고유형별 파서 분리
- **검증**: SH 청년매입임대 공개 목록(data.go.kr 15102880)을 **정답지**로 회귀 테스트
- **출력**: `unit` 레코드 (`status = parsed`)

### S4b — 자격요건 추출
공고문 PDF에는 호실 표만 있는 게 아니다. **입주 자격 · 소득·자산 기준 · 순위 · 가점 · 신청 절차**가 함께 실려 있고, 검색 수요는 이쪽이 더 크다(`매입임대 소득기준`, `행복주택 순위`).

- 표가 아닌 서술형이라 호실 파서와 **별도 경로**로 처리
- 섹션 헤딩 기반 분할 → 소득분위·자산 기준 수치 추출
- 요약은 **검수 큐를 반드시 경유**한다. 자격요건 오류는 사용자에게 실질적 피해를 준다
- **출력**: `eligibility` 레코드

### S5 — 정규화
- 주소: 도로명 우선, 지번 병기
- 단지 연결: `waitlist.complex_code`(hsmpSn) → `complex.id`. 단지정보 API를 시군구별로 받은 뒤 뒤늦게 붙어도 된다
- 금액: 정수 원 단위
- 면적: 소수 2자리
- 유형: 자체 코드로 매핑 — 행복주택 · 국민임대 · 매입임대 · 장기전세 · 통합공공임대 · 전세임대 · 든든전세

### S6 — 좌표 매칭 (오프라인)
**지오코딩 API를 호출하지 않는다.**

- 자체 보유한 위치정보 요약DB 좌표 테이블에 정규화된 도로명주소를 조인
- UTM-K(GRS80) → WGS84 변환 후 저장
- 매칭 실패 시: 건물명·지번 보조키로 재시도 → 그래도 실패하면 읍면동 중심 좌표로 강등
- `geo_precision`에 등급을 남긴다: `building` / `road` / `dong`
- **호실 페이지는 `building` 등급일 때만 색인한다**

### S7 — 검수 큐 (사람 개입)
파싱 신뢰도 미달 레코드는 자동 발행하지 않는다.

**큐로 보내는 조건**
- 표 컬럼 수 불일치
- 보증금 0원 또는 10억 원 초과
- 전용면적 9㎡ 미만 또는 200㎡ 초과
- 좌표 정확도가 `building` 미만
- 동일 공고 내 호실 수가 직전 회차 대비 ±50% 변동
- 자격요건 추출 결과 전부 (S4b는 무조건 경유)

승인/반려 후 **반려 사유를 파서 개선에 환류**한다.

### S8 — 발행
- 검수 통과분만 `published`로 전환
- 마감 공고는 삭제하지 않고 `closed`로 두어 URL 유지. 상단에 마감 배너 + 후속 공고 링크
- on-demand revalidate + 사이트맵 갱신

## 흐름 요약

```
S1 공고수집 ─► S2 상태·마감추적
   │
   └► S3 첨부수집 ─┬► S4  호실파싱 ──┐
                   └► S4b 자격요건   │
                                      ├► S5 정규화 ─► S6 좌표매칭 ─► S7 검수큐 ─► S8 발행
                                      ┘                                  ▲
                                                                    사람 개입
```

## 스크래핑 원칙

- 대상 사이트의 `robots.txt`와 이용약관을 먼저 확인한다
- 동시 요청을 걸지 않는다. 순차 요청 + 요청 간 간격 유지
- 첨부파일은 한 번만 내려받고 해시로 재다운로드를 피한다
- 실패 시 재시도는 지수 백오프, 최대 3회
