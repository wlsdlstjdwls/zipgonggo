> **SH주택정보는 단지에 있는 주택형을 다 준다. 공고는 그중 일부만 공급한다.** 그대로 실으면 지면이 거짓말을 한다 —
> 천왕이펜하우스 3단지는 제51차에서 84형 하나만 공급하는데 평면도 9장·실내 36장이 전부 나왔다(사용자 지적 2026-09-14).
> 지면은 공급현황의 `supply_type` 앞머리 숫자로 걸러 **공고에 있는 형만** 펼치고 나머지는 `<details>`로 접는다(감추지는 않는다).
> 실내 사진은 API가 주택형을 안 주고 이름 앞에 붙여 온다(`84A 안방`) — `load`가 그걸 꺼내 `sply_ty`에 넣는다.
> 이걸 안 하면 실내 36장이 전부 「주택형 없음」이 되어 걸러지지 않는다.

지면은 **한 영역, 한 줄**이다. 종류(평면도·전경·배치도·실내)를 세로로 쌓았더니 네 덩이가 지면을 다 먹어
탭으로 갈랐다(사용자 지적 2026-09-14). 「이 공고에 없는 주택형」도 맨 끝 탭으로 들어와 영역이 하나다.
안 고른 탭도 DOM에는 그려 두고 숨기기만 한다 — 빼면 크롤러가 그 사진들을 못 본다.

- **캡션은 탭 안에서 서로를 가르는 것만 진다.** 탭이 「실내」라고 말하고 있으면 `84A 거실`이 아니라 `거실`이다.
  실내 사진 이름 앞머리의 주택형은 `lib/complex-images.ts`가 떼어 낸다. 「다른 주택형」 탭만 종류가 섞여 `49 평면도`처럼 둘 다 붙인다.
- **줄은 끌어서 넘긴다.** 터치는 브라우저 기본 스크롤이 낫고(관성이 있다), 마우스는 그게 안 돼서
  — `overflow-x:auto`를 마우스로 끌면 스크롤이 아니라 글자가 선택된다 — 포인터로 `scrollLeft`를 직접 민다.
  끌고 난 뒤의 click은 사진 열기로 오해하지 않게 막는다. 넘칠 때만 양끝에 화살표를 띄운다 —
  띄우지 않으면 사진이 두 장뿐이라 끌 게 없는 탭(평면도)에서 「안 끌린다」로 읽힌다.
- **SH 실내 사진 원본은 작다.** 천왕이펜하우스 3단지 실측 650~772px(평면도는 1783px). 뷰어 이미지에
  `max-width`만 주면 큰 화면 한가운데 우표만 하게 떠서 「확대가 안 된다」가 된다. `width/height: 100%`로
  채우고, 원본이 1200px 미만이면 「원본이 650px이라 크게 보면 흐립니다」라고 아래에 적어 둔다.
- **누르면 전체화면 뷰어**(`components/photo-viewer.tsx`). 좌우 넘기기와 확대(핀치, 두 번 누르기, 휠, 확대한 채 끌기)를 직접 한다.
  **라이브러리를 안 쓴다.** web의 의존성은 `next`·`react`·`pg` 셋뿐이고 뷰어 하나 때문에 늘리지 않았다.
  smokespot의 `photo-lightbox.tsx`를 참고했지만 거긴 framer-motion을 쓰고 확대가 없어 제스처는 새로 짰다.
  뷰어는 지금 탭 안에서만 넘긴다 — 탭을 갈라 놓고 넘기기로 넘나들면 가른 뜻이 없어진다.

> **함정 1: `setPointerCapture`를 걸면 그 뒤 `pointerup`의 `target`이 잡은 요소로 바뀐다.** 뷰어에서 「여백을 누르면 닫기」를
> `e.target`으로 판정했더니 그림 위 탭도 여백으로 읽혀 두 번 누르기가 닫기가 됐다. 지금은 누르기 시작한 자리를
> **그려진 그림 상자**(`contentRect`)와 견줘 적어 둔다 — `object-fit: contain`이라 요소 상자에는 남는 여백이 있어 요소로 재면 또 틀린다.
>
> **함정 2: `setPointerCapture`는 throw할 수 있다**(이미 놓인 포인터 등). 그 자리에서 터지면 제스처가 통째로 죽어
> 확대도 끌기도 안 먹는다. 잡기·놓기 둘 다 try/catch로 감싼다.

> **AI로 없는 도면은 만든다.** 주거 결정 자료라 실해가 나고, 대량 생성 이미지는 검색 엔진의 scaled content abuse에 직격이다. AI를 쓸 자리는 (1) 받은 도면 스캔 정리, (2) 도면에서 방 개수·구조를 뽑아 구조화 필드로, (3) 공고문 면적 실수치 기반 **모식도**(「실제 도면 아님」 라벨 필수) 셋뿐이다. 화면에 AI로 만들고 화면에서는 AI가 만든 도면이라고 표기한다.

## 4. 좌표 — API가 아니라 데이터셋으로

**지오코딩 API 응답의 DB 저장은 금지된다. 파일 데이터셋으로 받은 좌표는 저장·재배포가 허용된다.**
같은 위경도라도 취득 경로가 권리를 정한다.

| 소스 | 방식 | 저장 | 조건 |
|---|---|---|---|
| **행안부 도로명주소 위치정보 요약DB** [15050410](https://www.data.go.kr/data/15050410/fileData.do) | 파일 | **가능** | 무료 · **공공저작물 제1유형(출처표시)** · 도로명주소 + 주출입구 X,Y · **business.juso.go.kr 이용목적 심사 필요** → [신청 가이드](phase0-신청가이드.md#1-도로명주소-좌표-신청--가장-오래-걸린다-오늘-접수해라) |
| 국토부 지오코더 API [15101106](https://www.data.go.kr/data/15101106/openapi.do) | 실시간 | **불가** | 일 40,000건 · "실시간 사용만 가능" |
| VWorld Geocoder | 실시간 | **불가** | "별도의 저장장치나 데이터베이스에 저장할 수 없습니다" (원문) |
| 카카오 로컬 | 실시간 | **불가** | "응답받은 결과 데이터를 별도로 저장하여 사용하는 것은 허용하지 않으며, 실시간 호출만 가능" |

**채택: 위치정보 요약DB를 내려받아 자체 좌표 테이블로 보유하고 주소를 오프라인 조인한다.**

> **지번주소는 검색 API로 한 번 표준화한다** (2026-09-10 구현). SH 공고문 소재지의 4분의 1이 지번으로만
> 적혀 있고(재개발 매입분·리츠분), 요약DB에는 지번 칸이 없어 그대로는 못 맞춘다. `business.juso.go.kr`
> 검색 API(`addrLinkApi.do`)에 지번을 물으면 `rnMgtSn`+`udrtYn`+`buldMnnm`+`buldSlno`가 오는데,
> 이게 요약DB `entrance`의 기본키다. **이 API는 좌표를 주지 않고 좌표제공 API는 쓰지 않는다** —
> 저장하는 좌표는 여전히 요약DB에서만 나오므로 「하지 말 것 1」에 걸리지 않는다.
> 구현은 `pipeline/src/zipgonggo_pipeline/geo/juso_search.py`, 스위치는 `s6_geocode --juso-api`.
> 실측(2026-09-10): 못 맞춘 168건 중 157건을 채웠다.

> **포털에서의 실제 명칭은 「도로명주소 출입구 정보」다** (확인됨). `business.juso.go.kr` → 주소정보 자료제공 → 주소정보 다운로드 →
> **「제공하는 주소 (도형, 좌표)」 탭**(기본 탭 아님). 스키마 19개 컬럼 중 좌표는 `ENTRC_POINT_X` / `ENTRC_POINT_Y`,
> 조인 키는 `ADR_MNG_NO`(26자리) 또는 `ROAD_NEW_CD`+`BULD_SE_CD`+`BULD_MNNM`+`BULD_SLNO` 복합키다.
>
> **⚠️ 한 종만 받으면 안 된다.** 상세 화면 원문: *"집합건물(예: 아파트)의 경우 주소기준의 주(보조)출입구 제공 / **건물단위제공 안함**"*
> 즉 아파트 단지 하나에 좌표가 하나만 붙어 101동과 115동이 같은 점이 된다. 공공임대 주력이 단지형 아파트라 이 상태로는 지도가 성립하지 않고
> 「하지 말 것 4」의 건물 단위 좌표 요건도 못 채운다.
> 동 단위 좌표는 같은 탭의 **「건물군 내 상세주소 동 도형」(SHP)** 에 있다 — **두 종을 함께 신청한다.**
>
> 좌표계는 **EPSG:5179 (Korea 2000 / Unified CS, UTM-K/GRS80)** 다 — **확인됨 (2026-09-09, 실측)**.
> 서울 종로구 자하문로 94의 `(953241.68, 1954023.47)`을 5179→4326으로 변환하면 `(126.9704, 37.5844)`로 실제 위치와 맞는다.
> 스키마에는 "문자 17"로만 적혀 있어 값으로 판정했다.
>
> **받은 파일과 실적 (2026-09-09).** 전체분 `RNENTDATA_2609_{시도코드}.txt` 16개 + 일변동분 `AlterD.JUSUEC.YYYYMMDD.…TXT` 8개.
> CP949 · `|` 구분 · 19칸. 건물 하나에 행 하나로 `(도로명코드, 지하여부, 본번, 부번)`이 전국 유일하다(서울 52.3만 행 전수 확인).
> `pipeline/src/zipgonggo_pipeline/geo/entrance.py`가 SQLite로 접는다 — **641만 행 · 1.16GB · 65초**. 좌표 칸이 빈 행 약 0.08%는 버린다.
> 일변동분의 이동사유코드는 31(신규)·34(변경)·63(폐지)이고 63은 지운다.
>
> **아직 동 단위는 못 받았다.** 지금 있는 건 주출입구 한 점뿐이라 아파트 단지의 101동과 115동이 같은 점이 된다.
> 「건물군 내 상세주소 동 도형」(SHP)을 받으면 그때 「하지 말 것 4」의 건물 단위 좌표 요건을 채운다.

실시간 API 방식은 산수가 안 맞는다 — 공고 지도 한 장에 마커가 476개면 페이지 1회 열람에 476콜, 일 방문 84명이면 40,000건 쿼터가 소진된다.

## 4b. 주변 시설 — 역·병원·영화관 (후보, 미착수)

사용자 요청 2026-09-09: 단지 상세에 "가까운 역 2~3개와 거리·도보 몇 분", "병원·영화관 같은 생활 편의시설".

**결론: 역은 할 수 있고, 편의시설은 조건부다.** 좌표는 이미 우리 손에 있으므로(4절 요약DB 조인, `notice_complex.geom`)
남은 건 상대 지점의 좌표를 어떻게 얻느냐 하나다. 그런데 **지오코딩 API로 얻은 좌표를 저장하지 않는다**(CLAUDE.md 하지 말 것 1)는
제약이 여기에도 그대로 걸린다 — 카카오 로컬·네이버 지역검색의 장소 좌표도 같은 규율이다.
그래서 판단 기준은 "그 데이터셋을 파일로 받아 오프라인 조인할 수 있는가"다.

| 후보 | 출처 | 파일로 받나 | 판정 |
|---|---|---|---|
| 도시철도 역사 좌표 | 국가철도공단 역위치 / 서울교통공사 역사마스터 (data.go.kr 파일데이터) | 예 (CSV) | **미확인** — 컬럼·좌표계 미열람 |
| 병원 | 건강보험심사평가원 병원정보서비스 (data.go.kr) | 예 | **미확인** |
| 영화관 | 영화진흥위원회 상영관 정보 | 예 | **미확인** |
| 그 외 생활 POI(카페·마트…) | 카카오 로컬 / 네이버 지역검색 | 아니오 (실시간 호출만) | **쓰지 않는다** — 저장 금지 규율 |

설계 메모 (착수할 때):

- 거리는 `ST_Distance(geography)` 하나면 끝난다. 역은 반경 1.5km 안 최근접 3개면 충분하다.
- **도보 분은 직선거리로 추정한 값이라고 밝혀 쓴다.** 실제 도보 경로는 유료 길찾기 API 영역이다.
  성인 보행 80m/분에 골목 우회 계수 1.3을 곱해 `ceil(거리 × 1.3 ÷ 80)` 정도가 무난하고, 화면에는 "도보 약 N분"으로 쓴다.
- 역·병원 좌표는 공고와 무관한 고정 자산이라 `notice_complex`가 아니라 별도 표(`poi`)에 두고 공고마다 다시 조인하지 않는다.
- 착수 전에 위 표의 **미확인**을 먼저 열람해 확인됨으로 바꾼다(CLAUDE.md 작업 전 확인).

## 5. 지도 SDK

| 기관 | robots.txt | 이용약관 | 저작권 정책 | 첨부 자동수집 | 사실 데이터 재구성 |
|---|---|---|---|---|---|
| LH | 첨부 경로 `Disallow` | 재가공·크롤링 조항 **없음** | 페이지 미발견 | **막힘** | 가능 |
| SH(서울) | `Allow: /` | — | 서울시 기본 **공공누리 제4유형** | 허용 | 가능 (원문 복제는 불가) |
| 청년안심주택 | 파일 없음 | — | 서울시 정책 준용 | 허용 | 가능 |

### LH — robots.txt가 유일한, 그러나 결정적인 제약

LH 이용약관(`lh.or.kr/menu.es?mid=a10802000000`) 제1~12조와 부칙을 훑었다.
게시물 복제·배포·2차 가공 조항도, 자동화 수단 이용 금지 조항도, 저작권 귀속 조항도 **없다.**
저작권 정책 페이지는 이용안내 하위 메뉴 어디에도 없고 푸터에도 링크가 없다 — **미확인**으로 남긴다.

약관이 비어 있으니 남는 제약은 robots.txt 하나인데, 그 하나가 하필 첨부파일 경로를 정확히 겨눈다.
목록·상세는 열어 두고 `lhFile.do`만 닫아 둔 것은 실수가 아니라 의도로 읽어야 한다.

**대응**: 첨부 자동 다운로드를 하지 않는다. 세 갈래가 남는다.

1. **파일데이터로 우회** — 15088707(모집공고)·15080989(단지정보)는 data.go.kr 배포본이라 robots.txt와 무관하다. 이용허락범위 제한 없음.
2. **상세 페이지 본문 파싱** — `selectWrtancInfo.do`는 허용 경로다. 첨부 안에만 있는 호실 표는 못 얻지만 공고 메타는 얻는다.
3. **수집 허용 문의** — LH에 재가공 목적을 밝히고 서면 회신을 받는다. 회신 전까지 LH 호실 파서는 착수하지 않는다.

> **로드맵 영향**: Phase 2의 파서 투입 순서 `SH → LH → GH`는 그대로 두되,
> LH 차례가 왔을 때 회신이 없으면 GH를 먼저 당긴다. LH 첨부 파싱은 회신에 종속된다.

### SH — 제4유형은 원문에 걸리고, 사실에는 걸리지 않는다

서울시 저작권 정책(`seoul.go.kr/helper/copyright.do`) 기본값은 **공공누리 제4유형: 출처표시 + 상업적 이용금지 + 변경금지**다.
서울주거포털 공고 목록 페이지 HTML을 뒤졌으나 공공누리 배지·유형 표기가 **부착되어 있지 않다.**
정책 원문은 미부착 자료에 대해 이렇게 규정한다:

> "공공누리가 부착되지 않은 자료들을 이용하고자 할 경우에는 공공저작물 관리책임관 및 실무담당자와 사전에 협의하여 이용해 주시기 바랍니다."

제4유형을 문자 그대로 받으면 이 서비스는 성립하지 않는다. 상업적 이용도 변경도 금지이기 때문이다.
다만 **제4유형이 걸리는 대상은 저작물이지 사실이 아니다.**
주소·전용면적·보증금·월임대료·마감일은 저작권 보호 대상인 창작적 표현이 아니라 사실 정보이고,
[하지 말 것 5](../CLAUDE.md)가 이미 "원문은 링크만, 사실 데이터만 재구성"으로 이 선을 그어 두었다.

**대응**: 기존 규칙을 유지하되 두 가지를 더한다.

- 모든 공고 페이지에 **출처 표시**와 기관 원문 링크를 넣는다 (제1유형이든 제4유형이든 공통 의무).
- 서울시 공공저작물 관리책임관에게 **사전 협의를 접수**한다. 정책이 명시적으로 요구하는 절차다.

> 이건 법률 자문이 아니다. 사실/표현 구분은 통상적 해석이고 서비스 규모가 커지면 자문을 받아야 한다.
