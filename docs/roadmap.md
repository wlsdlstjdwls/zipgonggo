# 로드맵

**지역이나 기관으로 좁히지 않는다. 범위를 깊이로 나눈다.**
1층은 API만으로 전국이 완성되고, 2층은 그 위에 호실 단위를 얹는다.
첫 배포부터 전국 서비스가 나오고, 가장 어려운 첨부파일 파싱이 출시를 막지 않는다.

## Phase 1 — 전국 1층

**목표**: API만으로 되는 것 전부. 첫날부터 전국.

**범위**
- 전국 17개 시도 · LH·SH·GH 전 기관
- 공고 · 단지 · 지역 · 지역×유형 페이지
- 마감 D-day, 발표일, 예비입주자 대기현황, 정정 이력
- **호실 단위 없음**

**산출물**: 수집 스케줄러(S1·S2) · 좌표 조인(S6) · 4개 페이지 템플릿 · 사이트맵 · 지도 컴포넌트

**진행 (2026-09-08)**: S1 수집기 ✅ (마이홈 API 185건 + SH 서울주거포털 79건) · `/` 목록 ✅ (공공/민간 탭, 카드 그리드, 최신 공고순 기본 + 마감 임박순 토글, 24건 커서 페이징 무한스크롤 `/api/notices`, 스켈레톤·페이드, 목록·옵션 1시간 `unstable_cache`) · `/notice/{slug}` 상세 ✅ · 디자인 토큰(라일락, Pretendard) ✅ (지도는 좌표 없이 브라우저 실시간 지오코딩, 요약DB 승인 후 S6로 교체) · S2 · 단지/지역 페이지 · 사이트맵 미착수. 로컬 `cd web && npm run dev` → http://localhost:3100

## Phase 2 — 호실 2층

**목표**: 첨부파일 파싱으로 호실 단위 확보

**범위**
- 기관별 파서를 **SH → LH → GH** 순으로 순차 투입
- 전국 커버는 1층에서 이미 확보돼 있으므로 파서 하나가 늦어도 서비스는 돈다
- **민간임대 스크래퍼 병행** (청년안심주택 게시판) — 파서와 독립이라 일정이 얽히지 않는다

> SH부터 시작하는 이유: 호실 단위 데이터가 정형 파일로 공개된 유일한 사례(data.go.kr 15102880)라 파서 출력을 대조해 정확도를 숫자로 잴 수 있다. 정답지가 없는 기관부터 시작하면 무엇이 틀렸는지조차 알 수 없다.

**산출물**: 기관별 파서 3종 · 민간임대 스크래퍼 1종 · 검수 큐 관리 화면 · 호실 상세 템플릿 · 골든 데이터셋 회귀 테스트

**완료 기준(DoD)**
| 지표 | 기준 |
|---|---|
| 파싱 정확도 (SH 공개목록 대조) | 95% 이상 |
| 검수 큐 유입률 | 10% 이하 |
| 색인 페이지 | 30,000 이상 |
| 월 세션 | 5,000 이상 |

**예상**: 6~10주

| 공고문 재가공물 게시가 약관상 허용된다 | **B**: 원문 첨부는 재배포하지 않고 링크만, 사실 데이터만 재구성 |

## 리스크

- **벤치마크의 실내 사진** — 유튜브 촬영으로 축적된 자산이라 단기간에 따라잡을 수 없다. 사진 대신 데이터 밀도와 최신성으로 경쟁한다
- **자동 생성 페이지의 검색엔진 평가** — 얇은 페이지 규칙을 지키지 않으면 3만 페이지가 통째로 저품질로 묶인다. **색인 페이지 수가 아니라 색인 대비 노출률을 지표로 삼는다**
- **마이홈포털 API 단일 의존** — Phase 1 전체가 여기 얹혀 있다
- **LH 첨부 수집 차단** — 로드맵 2층의 절반이 여기 걸려 있다. 회신이 늦으면 GH를 앞당겨 순서로 흡수한다
