# URL · 페이지 구조

## 규칙

**타입 세그먼트는 영어, 식별자는 한글.**

타입 세그먼트(`notice`·`complex`·`area`)는 사람이 읽지 않는 구조어라 짧은 영어가 안전하다.
식별자는 검색어와 글자 그대로 일치해야 하므로 한글로 둔다.
`/gonggo/`·`/danji/` 같은 로마자 표기는 한국어도 영어도 아닌 절충이라 채택하지 않는다.
공고 식별자만은 기관·연도·차수 조합이라 영숫자로 둔다.

```
/notice/{기관}-{연도}-{공고ID}-{주택번호}-{유형}   /notice/lh-2026-21174-1-gungmin
/notice/{공고}/{호실}                    /notice/sh-2026-02-maeip/1204
/complex/{단지명}-{단지코드}              /complex/서도휴빌3차-11200
/area/{시도}                              /area/서울특별시
/area/{시도}/{시군구}/{읍면동}            /area/서울/강동구/천호동
/area/{시군구}/{유형}                     /area/강동구/매입임대
/type/{유형}                              /type/매입임대
```

> **같은 이름의 시군구가 여러 시도에 있으면 세그먼트 앞에 시도 통칭을 붙인다** — `/area/울산 북구/국민임대`.
> 북구는 부산·울산·광주에, 동구는 넷에 있다. 이름이 하나뿐이면 붙이지 않는다(`/area/강동구/매입임대`).
> 붙일지 말지는 DB의 시군구 이름 중복 하나로 정하고, 판단하는 자리는 `web/src/lib/routes.ts`의
> `areaTypeSegment` 한 곳뿐이다(2026-09-16 구현). 지역 집계는 `notice.sigungu`가 아니라 `notice_area`로 센다 —
> 여러 시군구에 걸친 공고가 있어 앞엣것만 보면 시군구가 89개, `notice_area`로 보면 132개다.

> 식별자 자리는 원래 `{차수}`였으나 마이홈 API에 차수 필드가 없어 **공고ID + 주택일련번호**(API `pblancId`·`houseSn`)로 바꿨다(2026-09-08).
> 기관 세그먼트는 영문이면 소문자(`lh`), 한글 기관명(`충남개발공사`)은 그대로. 유형은 로마자 약칭(`maeip` `gungmin` `haengbok` `janggi` `tonghap` `jeonse` `deundeun` `yeonggu` `mingan` `50nyeon` `10nyeon` `6nyeon` `5nyeon` `gisuksa`).
> 정정공고는 별도 공고ID를 받으므로 URL도 따로 생긴다. 원공고 페이지 상단에 "정정공고 있음" 배너로 잇는다.

**URL은 한 번 만들면 죽이지 않는다.** 마감 공고도 `closed` 상태로 살려 두고 상단에 마감 배너와 후속 공고 링크를 붙인다. 연도별 공고 아카이브가 그 자체로 새 롱테일이 된다.

## 스코프와 필터

사용자가 고르는 값은 두 층으로 나눈다. 섞으면 필터 바가 평평해지고, 무엇이 페이지의 정체성인지 사라진다.

| 층 | 값 | 위치 | 색인 |
|---|---|---|---|
| **스코프** | 부문(공공임대/민간임대) + 시도 | URL 경로 | index |
| **필터** | 공급유형, 마감 임박, 정렬 | 쿼리스트링 | noindex |

스코프는 "지금 어느 판을 보고 있는가"라서 페이지 제목과 title에 그대로 들어간다.
필터는 그 판 안에서 결과를 좁히는 도구라 제목을 바꾸지 않는다.

- 스코프는 헤더 아래 상시 노출한다. 필터 바 안의 칩 하나로 두지 않는다.
- 마지막 스코프는 `localStorage`에 남긴다. **`/`의 서버 렌더는 이 값을 보지 않는다** — ISR 캐시 한 장을 모두가 공유하고, 크롤러와 공유 링크 수신자가 전국 목록을 봐야 하기 때문이다. 저장값 반영은 클라이언트에서만.
- 저장값 복원은 **파라미터 없는 `/`로 들어왔을 때만** 한다(`ScopeRestore`). 스코프가 실린 URL(`/area/{시도}`, `?sector=`)은 공유 링크라 덮지 않고,
  복원 뒤 URL에 스코프가 실리므로 다시 걸리지 않는다. **헤더 로고는 저장값을 지운다** — 홈이 곧 "전국"이라 이게 스코프 탈출구다.
- 기억하는 값은 스코프(부문+시도)뿐이다. 필터(유형·마감·정렬)는 그 판 안의 일회성 도구라 남기지 않는다.
- 부문은 양쪽에 공고가 쌓이기 전까지 갈림길 페이지를 만들지 않는다. 민간임대 0건인 채로 `/sector/민간임대`를 열면 빈 문이 하나 생길 뿐이다.

## 페이지 타입

### 호실 상세 `/notice/{공고}/{호실}` — 30,000+
- 고유 콘텐츠: 보증금 3종 · 임대료 · 전용면적 · 층 · 동호 · 지하철 도보시간 · 건물 좌표
- 롱테일: `서도휴빌 3차 202호 보증금` · `천호동 매입임대 43㎡ 월세` · `장안동 투룸 임대주택`
- title: `{단지명} {동}{호} 전용 {면적}㎡ 보증금·임대료 | {공고명}`
- meta: `{자치구} {법정동}, {유형}. 보증금 {기본}원 / 월 {임대료}원. 지하철 {역} 도보 {분}분.`
- JSON-LD: `Apartment` + `Offer`

### 공고 지도 `/notice/{공고}` — 300+
- 고유 콘텐츠: 전체 호실 지도 · 필터 · 접수일정 · **D-day** · 발표일 · 정정 이력 · **자격요건/소득기준 요약** · 원문 PDF 링크
- 롱테일: `2026 2차 매입임대 공고 지도` · `SH 장기전세 51차 위치` · `매입임대 소득기준`
- title: `{공고명} 지도 — 전체 {n}호실 위치·보증금 한눈에`
- meta: `{기관} {공고명}. 접수 {시작}~{마감}(D-{n}). {지역} {n}호실 지도.`
- JSON-LD: `ItemList` + `Event`

### 단지 `/complex/{단지명}-{단지코드}` — 4,000+
- 고유 콘텐츠: 단지 제원(세대수·동수·준공일) · **예비입주자 대기현황** · 역대 공고 이력
- 롱테일: `번동 5단지 국민임대 대기` · `서도휴빌 3차 임대료`
- title: `{단지명} {유형} 임대료·대기현황·역대 공고`
- JSON-LD: `ApartmentComplex`

### 지역 시도 `/area/{시도}` — 17
- 스코프 착지 페이지. 시도 전체 공고 목록 + 시군구 분포 + 유형 분포
- 롱테일: `서울 공공임대 모집공고` · `경기도 임대주택 공고`
- title: `{시도} {부문} 모집공고 {n}건 — 보증금·마감일 한눈에`
- 기준 미달(3건 미만) 시도는 생성하지 않고 `/`로 `301`
- JSON-LD: `CollectionPage`

### 지역 `/area/{시도}/{시군구}/{읍면동}` — 3,500
- 고유 콘텐츠: 해당 동 전체 매물 지도 · 보증금 중앙값 · 유형 분포 · 진행중 공고
- 롱테일: `강동구 천호동 임대주택` · `성남시 분당구 공공임대 모집`
- title: `{동} 임대주택 {n}곳 — 보증금·모집공고 지도`
- JSON-LD: `CollectionPage`

### 지역 × 유형 `/area/{시군구}/{유형}` — 2,000
- 고유 콘텐츠: 유형 한정 매물 · 해당 유형 자격요건 · 경쟁 강도
- 롱테일: `강동구 매입임대` · `수원시 행복주택 모집공고`
- JSON-LD: `CollectionPage`

### 유형 허브 `/type/{유형}` — 13 (2026-09-16 구현)
- 고유 콘텐츠: 제도 설명 · 자격 요건 · 전국 공고 현황 — **직접 작성**
- 글은 `web/src/lib/housing-types.ts`에 있다. **설명을 안 써 둔 유형은 DB에 공고가 있어도 404다** —
  목록만 있는 허브는 홈에 유형 필터를 건 것과 다를 바 없어 얇은 페이지가 된다
- 자격 요약은 시드(`supply_type`)에서 읽는다. 해마다 바뀌는 한도를 글에 박지 않는다
- JSON-LD: `Article` + `FAQPage`

### 필터 결과 `?type=&closing=&sort=`
- **noindex.** canonical은 파라미터 없는 스코프 URL로(`/` 또는 `/area/{시도}`)

### 관심 공고 `/my` — 1 (2026-09-18 구현)
- ★로 담아 둔 공고를 접수 마감 임박순으로 모아 보는 개인 화면. 목록은 **브라우저
  localStorage에만** 있다(`zipgonggo.saved.v1` — 화면 문구는 「관심 공고」지만 키는 안 바꾼다)
- 화면이 id 묶음을 `/api/notices/by-ids`에 물어 행을 받는다. 응답은 `private, no-store`
- **noindex, follow.** 사람마다 내용이 다르고 크롤러에겐 언제나 빈 화면이라 얇은 페이지다.
  robots.txt로 경로를 막지는 않는다 — 막으면 크롤러가 이 meta를 읽지도 못한 채 URL만 기억한다
- 사이트맵·RSS에 싣지 않는다

## 얇은 페이지 방지 규칙

자동 생성 페이지는 규칙을 안 지키면 3만 페이지가 통째로 저품질로 묶인다.
**색인 페이지 수보다 색인 대비 노출률을 지표로 삼는다.**

| 페이지 | 기준 | 미달 시 |
|---|---|---|
| 호실 상세 | 고유 필드 **8개 이상** & 좌표 **건물 단위** | `noindex`, 공고 지도의 앵커로만 노출 |
| 지역 시도 | 공고 **3건 이상** | 페이지 생성 안 함, `/`로 `301` |
| 지역 | 매물 **3건 이상** | 페이지 생성 안 함, 상위 시군구로 `301` |
| 지역 × 유형 | 매물 **5건 이상** | 지역 페이지로 canonical |
| 단지 | 공고 이력 1건 이상 & 세대수 확보 | 대기현황 없어도 생성, 해당 섹션만 미표시 |

**단지 상세는 호실 상세 자리를 대신 채우고 있어 그 기준(고유 필드 8개 + 건물 좌표)을 그대로 받는다.**
좌표가 없던 동안은 전량 `noindex`였는데, S6가 요약DB를 오프라인 조인해 좌표를 채운 뒤로 기준을 넘긴 장이 생겼다 —
실측 2026-09-16 기준 1,920장 중 **665장**이 index, 나머지는 `noindex`에 공고 지도의 앵커로만 남는다.
세는 필드와 판정식은 `web/src/lib/queries.ts`의 `COMPLEX_FIELDS` 한 곳이고, 사이트맵도 같은 식을 쓴다.

- **자동 생성 문장 비율** — 본문에서 템플릿 문장이 **60%를 넘지 않게** 한다. 초과분은 표·지도 등 데이터 블록으로 대체
- **출처 배지** — ① API 원본 ② 계산값 ③ 자동생성 문장 ④ 직접 작성 4종을 시각적으로 구분한다. 신뢰도와 심사 방어력이 함께 올라간다
