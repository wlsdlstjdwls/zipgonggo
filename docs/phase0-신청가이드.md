# Phase 0 신청 가이드

로드맵의 선행 조건을 **실제로 어디서 무엇을 누르는지** 수준으로 풀어 쓴 문서다.
각 항목의 화면·명칭·필드는 2026-09-04에 직접 열어 확인했다. 확인하지 못한 것은 그렇다고 적었다.

착수 순서는 **1 → 2 → 3 → 4 → 5** 다. 1번이 가장 오래 걸리고 나머지 전부가 여기 얹혀 있다.

## 1. 도로명주소 좌표 신청 — 가장 오래 걸린다, 오늘 접수해라

### 무엇을 신청하는가

`data-sources.md`가 "위치정보 요약DB"라고 부르는 것은 **주소기반산업지원서비스 포털에서 「도로명주소 출입구 정보」라는 이름으로 제공된다.** 공공데이터포털 [15050410](https://www.data.go.kr/data/15050410/fileData.do)은 안내문일 뿐이고, 실제 파일은 거기서 받지 않는다.

포털 안내 원문:

> "위치정보요약DB는 도로명주소법 시행령에 따라 이용목적 심사를 거쳐야 제공 가능합니다."

**이용허락범위는 공공저작물 제1유형(출처표시)** — 상업적 이용과 변형이 모두 허용된다. 우리가 좌표를 DB에 저장할 수 있는 유일한 근거다.

### 화면 경로

```
https://business.juso.go.kr
  └ 상단 메뉴 「주소정보 자료제공」
      └ 「주소정보 다운로드」
          → https://business.juso.go.kr/jst/jstAddressDetailsSearch
```

이 화면에 탭이 두 개다. **기본값은 왼쪽이고, 우리가 쓸 것은 오른쪽이다.**

| 탭 | 내용 | 심사 |
|---|---|---|
| 공개하는 주소 (속성) | 도로명주소한글DB·건물DB·주소DB 등 13종. 좌표 없음 | 없음 (즉시 다운로드) |
| **제공하는 주소 (도형, 좌표)** | 출입구 좌표·건물 도형 등 4종 | **있음 (이용목적 심사)** |

「제공하는 주소 (도형, 좌표)」에 들어 있는 4종:

| 항목 | 형식 | 내용 |
|---|---|---|
| **도로명주소 출입구 정보** | TXT | 도로명주소 기준 출입구 좌표 |
| **건물군 내 상세주소 동 도형** | SHP | 집합건물(아파트) 내 동별 도로명주소 도형 |
| 도로명주소 건물 도형 | SHP | 건물 도형. 집합건물은 건물군 단위 |
| 사물주소 시설 기준점 | TXT | 버스정류장 등 사물주소 |

### ⚠️ 두 종을 같이 신청해야 한다

「도로명주소 출입구 정보」 상세 화면의 경고 문구를 그대로 옮긴다:

> "※집합건물(예: 아파트)의 경우 주소기준의 주(보조)출입구 제공 / **건물단위제공 안함**"

**출입구 정보만 받으면 아파트 단지 하나에 좌표가 하나 붙는다.** 101동과 115동이 같은 점을 가리킨다는 뜻이다.
공공임대는 단지형 아파트가 주력이라 이 상태로는 지도가 성립하지 않고, 「하지 말 것 4」의 "호실은 건물 단위 좌표" 요건도 못 채운다.

동 단위 좌표는 **「건물군 내 상세주소 동 도형」(SHP)** 에 있다. 설명 원문:

> "집합건물(예: 아파트) 내 동이 부여된 도로명주소…"

**따라서 신청 시 두 항목을 함께 장바구니에 담는다.** 하나만 담고 심사를 통과하면 다시 신청해야 하고, 그만큼 또 기다린다.

### 절차

1. `business.juso.go.kr` 접속 → 우측 상단 **마이페이지**에서 회원가입·로그인 (휴대폰 본인인증 또는 아이핀)
2. 「주소정보 자료제공」 → 「주소정보 다운로드」
3. **「제공하는 주소 (도형, 좌표)」 탭으로 전환** (기본값 아님, 반드시 클릭)
4. 「도로명주소 출입구 정보」 → 「자세히 보기」 → 데이터 다운로드에서 **전체** 선택 후 원하는 시점 클릭 → 장바구니 담김
5. 목록으로 돌아가 「건물군 내 상세주소 동 도형」도 같은 방식으로 담기
6. 우측 하단 장바구니 → **「신청하기」**
7. 이용목적 심사 → 승인 후 다운로드

> **미확인**: 신청 폼의 구체적 입력 항목(이용목적 서술 분량, 첨부 서류 유무)과 심사 소요기간은 로그인 이후 화면이라 확인하지 못했다. 접수하면서 실제 화면을 보고 이 문서에 적어 넣을 것.

### 이용목적에 쓸 내용

심사가 이용목적을 본다. 아래를 다듬어 쓴다.

> 공공임대주택 입주자모집공고 정보를 지역·단지 단위로 재구성해 일반 이용자에게 무료로 제공하는 웹 서비스를 운영합니다.
> 공고에 기재된 주소를 지도상에 표시하기 위해 도로명주소별 출입구 좌표 및 집합건물 동 도형이 필요합니다.
> 좌표는 주소 문자열과의 오프라인 결합에만 사용하며, 출처(행정안전부 도로명주소)를 서비스 화면에 표시합니다.

### 받은 뒤

- 스키마(직접 확인한 19개 컬럼):

  | # | 컬럼 | 한글 | 비고 |
  |---|---|---|---|
  | 1 | `ADR_MNG_NO` | 도로명주소관리번호 | 26자리, PK1 |
  | 2~6 | `ADM_CD` `CTP_KOR_NM` `SIG_KOR_NM` `EMD_KOR_NM` `LI_KOR_NM` | 법정동코드·시도·시군구·읍면동·리 | |
  | 7~8 | `ROAD_NEW_CD` `RN_NM` | 도로명코드(PK2)·도로명 | |
  | 9 | `BULD_SE_CD` | 지하여부 | PK3 · 0 지상 / 1 지하 / 2 공중 / 3 수상 |
  | 10~11 | `BULD_MNNM` `BULD_SLNO` | 건물본번(PK4)·건물부번(PK5) | |
  | 12~14 | `BSI_ZON_NO` `EFFECT_DE` `CHG_RES_CD` | 우편번호·효력발생일·이동사유 | 31 신규 / 34 수정 / 63 폐지 |
  | 15~17 | `ENT_MAN_NO` `ENTRC_SE` `ENTRC_TY` | 출입구일련번호·구분·유형 | `RM` 주출입구 · 01 공용 / 02 차량용 |
  | 18~19 | **`ENTRC_POINT_X` `ENTRC_POINT_Y`** | **출입구좌표 X·Y** | 17자리 문자 |

- 조인 키는 `ADR_MNG_NO` 단일 컬럼 또는 `ROAD_NEW_CD` + `BULD_SE_CD` + `BULD_MNNM` + `BULD_SLNO` 복합키다. LH 단지정보 API가 주는 `rnAdres`(도로명 문자열)를 이 복합키로 정규화해 붙인다.
- `CHG_RES_CD = 63`(폐지)는 조인 대상에서 제외한다.
- **좌표계 확인 필요.** 스키마에는 형식이 "문자 17"로만 적혀 있다. 기존 문서는 GRS80 UTM-K로 적어 뒀으나 화면에서 확인하지 못했다. 상세 화면의 **「활용가이드 다운로드」** 버튼으로 받아 EPSG 코드를 확인하고, PostGIS 적재 시 `ST_Transform`으로 4326 변환 여부를 결정한다.
- 파일은 `pipeline/data/`에 두고 커밋하지 않는다. 매칭에 성공한 좌표만 Postgres로 넘긴다.

## 2. 마이홈포털 API 3종 활용신청

### 좋은 소식 — 셋 중 둘은 운영계정도 자동승인이다

기존 문서는 "운영단계 심의승인"으로 뭉뚱그려 뒀는데, 각 데이터셋을 열어 보니 다르다.

| 데이터셋 | ID | 개발단계 | 운영단계 |
|---|---|---|---|
| 공공주택 모집공고 조회 | [15108420](https://www.data.go.kr/data/15108420/openapi.do) | 자동승인 | **자동승인** |
| 예비입주자 대기현황 | [15108378](https://www.data.go.kr/data/15108378/openapi.do) | 자동승인 | **자동승인** |
| 공공임대주택 단지정보 조회 | [15110581](https://www.data.go.kr/data/15110581/openapi.do) | 자동승인 | **심의승인** |

심의를 기다려야 하는 건 **단지정보 1건뿐**이다. 「마이홈포털 API 운영계정 심의」가 Phase 1 전체를 막는 리스크는 생각보다 작다.

### 절차

공공데이터포털 표준 절차다. **PC에서만 신청된다.**

```
오픈API 검색 → 개발계정 활용신청 → (자동승인) → 인증키 발급
  → 개발·테스트 → 운영계정 활용신청 → (자동/심의)
```

1. `data.go.kr` 로그인 (회원가입 필요)
2. 위 3개 링크 각각에서 우측 상단 **「활용신청」**
3. 활용목적 선택 + 서술, 상세기능 체크
4. 즉시 승인 → **마이페이지 → 오픈API → 개발계정**에서 인증키 확인
5. 인증키를 `.env`의 `DATA_GO_KR_KEY`에 넣는다 (`.env.example`에는 플레이스홀더만)

### 붙임 파일 — 요청 코드표다 (2026-09-08 정정)

받아서 열어 보니 **요청 파라미터 코드표**(시도·시군구 코드 258행, 주택유형·공급유형·월임대료구분 코드)뿐이고 응답 필드는 없다.
응답 스키마는 페이지 소스에 박힌 swagger JSON에 있어 `docs/api-spec/*.swagger.json`으로 뽑아 뒀다. 그래도 코드표는 요청에 필요하니 받는다. **활용신청 화면 하단 「참고문서」.**

```
붙임1. 요청 파라미터 코드(공공주택 모집공고)_260701.xlsx
붙임1. 요청 파라미터 코드(공공임대주택 단지정보)_260701.xlsx
붙임1. 요청 파라미터 코드(예비입주자 대기현황)_260701.xlsx
```

셋 다 `docs/api-spec/`에 들어 있다. 컬럼 확정 근거는 xlsx가 아니라 같은 폴더의 swagger JSON과 `samples/`다.

### 트래픽

개발계정 1,000건/일. 운영계정은 "활용사례 등록시 신청하면 트래픽 증가 가능" — 즉 **서비스를 먼저 띄우고 활용사례를 등록해야 한도가 올라간다.** 전국 백필은 운영계정 전환 이후로 잡는다.

## 3. 도메인 등록

`zipgonggo.kr`은 **미등록 상태다.** KISA/KRNIC WHOIS에 직접 질의해 확인했다:

> "상기 도메인이름은 등록되어 있지 않습니다."

`.kr`은 국내 등록대행자(가비아·후이즈·아사달 등)를 통해서만 등록된다. 연 2만 원 안팎.

- `.kr`과 `.co.kr` 중 **`.kr`** 을 쓴다. 짧고, 서비스명과 1:1이다.
- 등록 즉시 Vercel에 연결할 필요는 없다. 선점이 목적이다.
- 확인 시점이 2026-09-04다. 시간이 지났으면 등록 전에 다시 조회한다.

## 4. 기관 문의 두 건

[약관·저작권 판정](data-sources.md#6-약관저작권-판정)에서 나온 후속 조치다. 회신에 시간이 걸리니 1·2번과 같이 보낸다.

### 4-1. LH — 첨부파일 수집 허용 여부

LH `robots.txt`가 첨부 다운로드 경로(`/lhapply/lhFile.do`)를 막고 있다. 이용약관에는 관련 조항이 없어 **의사를 직접 물어야 한다.**

접수처: LH 홈페이지 문의 게시판 또는 국민신문고(`epeople.go.kr`).

> 「LH청약플러스」의 입주자모집공고 첨부파일(HWP/PDF)을 자동화된 방식으로 수집해
> 주소·면적·보증금·임대료 등 사실 정보만 추출·재구성하여 무료 정보 서비스에 게시하고자 합니다.
> 원문 첨부파일 자체는 재배포하지 않고 LH 원문 페이지로 링크만 연결합니다.
>
> 현재 `apply.lh.or.kr/robots.txt`가 `/lhapply/lhFile.do` 경로를 `Disallow`로 지정하고 있어 문의드립니다.
>
> 1. 위와 같은 목적의 첨부파일 자동 수집이 허용되는지
> 2. 허용된다면 준수해야 할 요청 간격·시간대 등 조건이 있는지
> 3. 별도의 데이터 제공 채널(파일 제공, API 등)이 있는지

**회신이 올 때까지 LH 호실 파서는 착수하지 않는다.** 회신이 늦으면 Phase 2 순서에서 GH를 앞당긴다.

### 4-2. 서울시 — 공공저작물 사전 협의

서울시 저작권 정책 기본값이 **공공누리 제4유형(상업적 이용금지 + 변경금지)** 인데, 서울주거포털 공고 페이지에는 공공누리 배지가 붙어 있지 않다. 정책 원문이 이 경우를 규정한다:

> "공공누리가 부착되지 않은 자료들을 이용하고자 할 경우에는 공공저작물 관리책임관 및 실무담당자와 사전에 협의하여 이용해 주시기 바랍니다."

접수처: 서울시 응답소 또는 국민신문고. 소관은 SH·주택정책실.

> 서울주거포털에 게시되는 공공임대주택 입주자모집공고에 대해 문의드립니다.
> 공고문 원문이나 첨부파일을 재배포하지 않고, 주소·전용면적·보증금·월임대료·모집일정 등
> 사실 정보만 추출해 지역·단지 단위로 재구성한 무료 정보 서비스를 준비 중입니다.
> 원문은 서울주거포털 링크로 연결하고, 모든 페이지에 출처를 표시합니다.
>
> 해당 게시물에 공공누리 유형이 부착되어 있지 않아 사전 협의 절차에 따라 문의드립니다.
>
> 1. 위 이용이 가능한지
> 2. 적용되는 공공누리 유형이 무엇인지
> 3. 출처 표시 문구에 지정된 형식이 있는지

## 5. 인프라 계정 — 반나절이면 끝난다

### 5-1. 네이버 클라우드 플랫폼 Maps

- `ncloud.com` 가입 → 콘솔 → **Services → Application Services → Maps** → 이용 신청
- **Application 등록** 후 Web Dynamic Map 활성화, 서비스 URL(개발용 `http://localhost:3000`, 배포용 도메인)을 등록해야 키가 동작한다
- 발급된 Client ID를 `.env`의 `NAVER_MAP_CLIENT_ID`에 넣는다

**확인해야 할 것**: 무료 이용량은 **대표계정(Maps를 처음 사용한 계정) 1개에 한해서만** 제공되고, API별로 월 3,000건~1억 건으로 편차가 크다. Web Dynamic Map의 정확한 건수는 콘솔 요금 화면에서 직접 봐야 한다 — FAQ 본문을 열지 못했다.

이 서비스는 **모든 페이지에 지도가 뜨므로 지도 로드 수 = 페이지뷰**다. 확인한 숫자를 월 페이지뷰 목표와 대조해 보고, 한도가 낮으면 지도를 사용자 클릭 시에만 로드하는 지연 로딩으로 설계를 바꾼다. (Web Dynamic Map은 지도 로딩 시점에만 과금되고 이후 zoom·marker 조작은 카운트되지 않는다.)

### 5-2. Neon + PostGIS

```sql

```

- **실제로 간 경로(2026-09-08)**: `neon.tech` 직접 가입이 아니라 Vercel Marketplace 통합.
  ```
  cd web
  vercel project add zipgonggo && vercel link --yes --project zipgonggo

  vercel env pull <임시파일>   # DATABASE_URL·DATABASE_URL_UNPOOLED 등 19개 주입됨
  ```
  플랜 ID는 `free`가 아니라 `free_v3`다. `vercel env pull`은 `.env.local`을 통째로 덮어쓰니 임시 파일로 받아 필요한 키만 옮긴다.
  Neon CLI가 `web/.agents/` `web/.claude/skills/` `skills-lock.json`을 심는데 전부 지웠다 — 저장소 규칙서는 루트 `CLAUDE.md` 하나다.

- SQL Editor에서 위 구문 실행 → `SELECT postgis_version();`으로 확인
- Connection string을 `.env`의 `DATABASE_URL`에 넣는다 (`?sslmode=require` 포함)
- `db/migrations/0001_init.sql` 적용

> **확인됨 (2026-09-08)**: `CREATE EXTENSION postgis` 통과. PostgreSQL 18.6 · PostGIS 3.6.0 (GEOS·PROJ 포함). `geography` 거리 계산 검증(서울시청–부산시청 324,915 m). Supabase 대안 불필요.
